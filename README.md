# 디펜스 배틀 (Defense Battle)

몹을 상대 전장에 던지고, 내 전장은 소환·합성한 유닛으로 막는 1:1 디펜스 대전.

저장소: GitHub [Jujeongmin/DefenseBattle](https://github.com/Jujeongmin/DefenseBattle) · Verse8 GitLab `RandomDefense-1783589010696` (플랫폼이 만든 이름이라 그대로, `develop` 브랜치)

Verse8(Agent8) 플랫폼용 하이브리드 캐주얼 디펜스 게임. **TypeScript + Vite** 클라이언트와
**Agent8 GameServer**(`server/`)로 구성된다. 기획 의도·KPI·퍼블리싱 피치는 [`docs/GDD.md`](docs/GDD.md) 참고.

- 소환 → 합성 → 강화 → 배치로 사각 링을 도는 몹 웨이브를 막는다 (몹 100마리 누적 시 패배)
- **캠페인** 3챕터 × 10스테이지 (별 3개 도전, 첫 클리어 보상, 유닛 해금)
- **유닛 컬렉션** 32종 (일반 8 · 희귀 10 · 영웅 8 · 전설 6), 덱 4슬롯 · 추천 덱, 상자·뽑기 카드로 레벨업
- **몹 카드** 16종, 4장을 골라 대전에서 상대 전장에 던진다 (카드마다 막는 유닛이 다름)
- **PvP 실시간 1:1** (같은 웨이브를 동시에 막으며 몹을 보내 상대를 무너뜨림), 트로피·티어·시즌 패스·랭킹
- **무한 모드** 50웨이브 생존
- **수익화**: Verse8 VX Shop 결제 + Verse8 Ads(보상형)

## 실행

```bash
npm install
npm run dev        # 개발 서버 (DEV 전용 디버그 버튼·가짜 광고 활성)
npm run typecheck  # 타입 검사
npm run build      # 타입검사 + 프로덕션 빌드 → dist/

# 게임 서버 (PvP/클라우드 저장/결제 지급)
cd server && npm install
npm run build && npm test   # gameserver-node 로컬 러너로 테스트 (isolated-vm)

# 밸런스 시뮬레이터
npx tsx tools/simulate.ts 20          # 무한 모드: 연구 진척별 도달 웨이브
npx tsx tools/simulate.ts stages 8    # 캠페인: 스테이지별 클리어율/별 (연구 × 유닛 레벨)
SIM_HPG=0.12 npx tsx tools/simulate.ts 20   # HP 성장률 실험
```

`VITE_AGENT8_VERSE` 가 없으면 **오프라인 모드**: localStorage 저장, 데모 VX(1000)로 결제 흉내,
PvP 는 AI 연습전만 가능. Verse8 프로젝트(.env 에 `VITE_AGENT8_VERSE`)에서는 자동으로
게임서버·VX Shop·Ads 가 활성화된다.

## Verse8 연동

### 1) 게임 서버 (`server/`)
`@agent8/gameserver-node` 형식(`export class Server`). 배포 시 Verse8 도구가
`npx -y @agent8/gameserver-node build` → `npx -y @agent8/deploy` 로 올린다.

| 함수 | 설명 |
| --- | --- |
| `loadProfile` / `saveProfile` | 계정 클라우드 저장 (pvp 필드는 서버 권위) |
| `$onItemPurchased(event)` | VX Shop 결제 완료 훅 → `pendingPurchases` 기록 |
| `claimPurchases` | 대기 구매를 가져가고 비움 (클라는 `purchaseId` 로 중복 지급 방지) |
| `pvpQueue` / `pvpPoll` / `pvpCancel` | 트로피 근접 매칭 (대기 시간에 따라 허용 폭 확대) |
| `pvpReady` / `pvpSnap` / `pvpAttack` / `pvpDefeat` | 룸: 동시 시작·상태 중계·몹 보내기·패배 보고 |
| `onRoomLeave` | 경기 중 이탈 → 상대 승리 |
| `pvpLeaderboard` | `pvpRanking` 컬렉션 상위 50 |

### 2) VX Shop 상품 등록
Verse8 VX Shop 에 아래 **productId** 로 상품을 등록해야 한다 (가격은 등록값이 표시에 우선).
가격은 100 VX = 1달러 기준. 상점의 '효율 N%' 는 기본 보석 상품(100 VX = 보석 100) 대비 가치로,
`config.ts` 의 `productEfficiency` 가 등록 가격으로 계산한다. 상품 이미지: `launch/vxshop/{productId}.png` (1:1).

| --- | --- | --- | --- | --- |
| `starter_pack` | 보석 150 + 소환권 10 + 골드 부스터 1 | 100 | 1 | 300% |
| `monthly_pass` | 즉시 보석 300 + 30일간 매일 보석 40 | 500 | - | 300% |

| `summon_ticket_pack` | 소환권 24장 | 200 | - | 120% |
| `mythic_ticket` | 신화 확정 소환권 1장 | 500 | - | 120% |
| `gold_booster_pack` | 골드 부스터 5개 | 200 | - | 125% |

| `crystal_2600` / `crystal_7000` / `crystal_15000` | 보석 2,600 / 7,000 / 15,000 | 2000 / 5000 / 10000 | - | 130 / 140 / 150% |
| `offer_comeback` | (팝업 24시간 한정) 보석 300 + 소환권 10 + 골드 부스터 2 | 200 | - | 250% |
| `offer_arena` | (팝업 24시간 한정) 보석 1,000 + 신화 확정 소환권 1 | 500 | - | 320% |
| `offer_chapter` | (팝업 24시간 한정) 보석 800 + 소환권 30 + 골드 부스터 4 | 500 | - | 260% |
| `unit_ranger` | 레인저 즉시 해금 + Lv5 + 보석 200 | 300 | 1 | 300% |

| `unit_bomber` | 폭격수 즉시 해금 + Lv5 | 500 | 1 | 320% |
| `unit_assassin` | 암살자 즉시 해금 + Lv5 | 700 | 1 | 314% |

**결제 팝업** (`offers.ts`, 빈도 '보통'): 판이 끝날 때 최대 하나, 같은 한정 상품 팝업은 하루 한 번.
- 2연패(대전) / 스테이지 2연속 실패 → `offer_comeback`,  새 아레나 승급 → `offer_arena`,  새 챕터 도달 → `offer_chapter` (승급·챕터가 연패보다 우선)
- 강화·연구·해금 버튼을 보석이 모자랄 때 누르면: 해금 중인 유닛이면 그 유닛 패키지, 아니면 모자란 만큼을 채우는 가장 작은 보석 상품
- 뜬 한정 상품은 24시간 동안 상점 '한정 특가' 칸에 남은 시간과 함께 보인다

### 3) 광고 플레이스먼트 (`ads.ts` `AD_PLACEMENTS`)
`reward_double`(결과 보상 2배), `reward_revive`(실패 시 1회 부활), `reward_ticket`(하루 3회 소환권 5장). 전면 광고는 쓰지 않는다. Verse8 대시보드의 placementId 와 맞춘다.

## 로비와 진행 (대전 중심)

- 로비 = 아레나 카드(**대전 시작**, 트로피 로드 바, 시즌 패스) + 캠페인 · 무한 모드 카드 (1-1 튜토리얼 전엔 튜토리얼 버튼만).
  하단: 상점 / 덱 / 연구 / 퀘스트 / 로드 / 랭킹 - 메뉴는 해금되면 NEW 로 하나씩 등장 (`FEATURE_UNLOCK`: 1-1 덱·대전, 1-2 연구, 1-3 퀘스트, 1-10 무한 모드)
- 유닛 해금: 트로피 로드 또는 캠페인 스테이지 클리어 중 먼저 닿는 쪽 (보석으로 조기 해금도 가능)
- **덱**: 유닛 덱(최대 4)과 몹 카드 덱(4장)을 카드를 칸으로 끌어다 놓아 편성 (칸끼리 끌면 교체, 칸 밖으로 끌면 빼기)
- **추천 덱** (`UNIT_PRESETS` 6개 · `ATTACK_PRESETS` 4개): 덱 화면 '추천 덱' 버튼. 다 가진 덱은 바로 장착, 없는 카드는 잠금 표시
- 몹 카드의 '막는 유닛' 아이콘, 유닛 카드의 스킬 ? 는 마우스를 올리거나 탭하면 말풍선 (`tooltip.ts`)
- 대전 상대는 온라인이면 8초 매칭 후 봇, 오프라인이면 바로 봇 - 봇은 실제 유저처럼 보이고 트로피가 오르내린다
  (Verse8 에선 `pvpBotStart`/`pvpBotResult` 로 서버가 트로피를 관리)
- **트로피 로드**(`TROPHY_ROAD`): 보석 + 유닛 해금(레인저 30 · 빙결술사 120 · 성기사 300 · 폭격수 550 · 암살자 850)
  + 몹 카드 해금(유령 60 · 방패병 180 · 광폭 오크 240 · 망령 400 · 그림자 도적 470 · 어둠 신관 650 · 점멸 마녀 690
  · 돌 골렘 900 · 고블린 킹 950 · 수호 주술사 1050 · 마왕 1200 · 번식 유령 1300)
- **진행 검증** (`npx tsx tools/progsim.ts both|pvp [실력] [시간]`, 실력 0.35): 대전만 하면 유닛 5종 약 2.5시간 · 마왕 약 6시간,
  캠페인을 같이 하면 스테이지 보상으로 유닛이 더 빨리 열리고(암살자 약 2시간) 캠페인 전부 약 3.5시간. 대전 승률 초반 70~80% → 이후 약 55%
- 봇 핸디캡: 실력 0.05~0.85 (300 트로피 ≈ 0.3, 1125+ ≈ 0.85), 유닛 공격력 62~100%, 유닛 레벨 = 내 덱 평균
- 첫 3판은 가장 약한 봇 (처음 대전에서 이기는 경험), 첫 대전엔 카드를 끌어 던지는 손가락 안내
- 대전 화면: 상대 창 아래에 상대 몹 카드 4장(빨간 테두리)과 유닛 덱 - 무엇이 날아올지·무엇으로 막는지 보고 카드를 고른다
- 던진 몹은 하늘에서 떨어진다: 받는 쪽엔 착지 지점에 0.8초 경고 고리, 던진 쪽엔 포물선 + 상대 창 흔들림

**몹 카드 16종** (`ATTACKS`) - 시작 4장(고블린 무리 · 질주 엘프 · 거인 · 분열 알) + 로드 12장.
새 6종 그림 중 3장은 기존 몹 색을 바꾼 카드 전용 그림(`CARD_ONLY_VARIANTS` - 웨이브·보스 그림은 그대로).
카드마다 잘 막는 유닛이 달라(카드 화면 '막는 유닛') 상대 덱을 보고 고른다. 봇도 상대 덱에 카운터가 없는 카드를 고른다.

| 카드 | 골드 | 특징 | 막는 유닛 |
|---|---|---|---|
| 고블린 무리 | 40 | 약한 몹 8마리 | 마법사·폭격수 |
| 질주 엘프 | 50 | 아주 빠른 몹 4마리 | 빙결술사·전사 |
| 거인 | 80 | 느리고 단단함 | 암살자·성기사 |
| 분열 알 | 70 | 죽으면 작은 몹 3마리 | 폭격수·마법사 |
| 유령 | 60 | 물리(전사·궁수·레인저·암살자) 피해 -60% | 마법사·빙결술사 |
| 방패병 | 65 | 화살(궁수·레인저) 피해 -60% | 마법사·폭격수·전사 |
| 망령 | 60 | 한 번 되살아남 | 폭격수·궁수 |
| 어둠 신관 | 90 | 주변 몹 초당 6% 회복 | 암살자·레인저 |
| 고블린 킹 | 120 | 4초마다 졸개 3마리 | 레인저·성기사 |
| 마왕 | 140 | 아주 강함, 쿨타임 15초 | 성기사·암살자 |
| 그림자 도적 | 60 | 4초마다 1.8초 숨음 (직접 못 노림, 범위 공격엔 맞음) | 마법사·폭격수·화염술사 |
| 돌 골렘 | 85 | 단단함 + 마법(마법사·번개·폭격·화염·대마법사·폭풍왕) 피해 -60% | 기사·창병·암살자 |
| 광폭 오크 | 70 | 체력 절반 아래면 1.9배 빨라짐 | 빙결술사·시간술사·암살자 |
| 점멸 마녀 | 65 | 3초마다 길을 따라 110px 순간이동 | 빙결술사·시간술사·번개술사 |
| 수호 주술사 | 95 | 주변(130px) 다른 몹 받는 피해 -35% | 레인저·석궁병·암살자 |
| 번식 유령 | 75 | 5초 뒤 한 번 복제 (복제는 2대까지 → 1장에 최대 6마리) | 레인저·대포병·사신 |

카드별 승률은 `npx tsx tools/cardsim.ts [판수] [트로피]` (봇이 카드 한 종만 쓸 때).

**PvP 밸런스 (`npx tsx tools/pvpsim.ts [판수] [플레이어실력]`)** - 플레이어(실력 0.55) 대 봇 시뮬레이션:
한 판 약 3~4분(PvP 시작 체력 x3, 웨이브당 +25%, 봇은 21~38초마다 골드를 모아 던짐), 승률 약 51~56%,
유닛 5종 해금(260 트로피)까지 약 1.2~2.6시간, 몹 카드 마지막(360)까지 약 2~3.5시간 + 튜토리얼/연습 ≈ 핵심 플레이 3시간.

## 로딩 화면 · 에셋

- 시작하면 로딩 화면(키아트 + 진행 막대 + 팁)에서 `game/public` 의 모든 그림·소리·글꼴을 미리 받고 서버 접속까지 끝낸 뒤 로비가 열린다 (`preload.ts`, 파일 목록은 `vite.config.js` 의 `virtual:public-assets`).
- 새 그림을 넣은 뒤엔 `python tools/optimize_png.py` (256색 이하는 무손실 팔레트, 상점 그림은 256색) - PNG 2.0MB → 0.98MB.

## 경제 보안 (서버 권위)

보석·아이템·카드·유닛 레벨·연구·상자·보상 수령은 **서버가 계산하고 저장**한다 (`server/src/server.ts` 의 `econ`).
- 계정별 서버 상태 `econ` 에만 있고, 기기는 읽기만 한다 (Verse8 SDK 는 상태를 쓸 수 없고 서버 함수만 부를 수 있다).
  `saveProfile` 로 올라온 저장본의 경제 필드는 버린다 → 저장값을 고쳐 올려도 반영되지 않는다.
- 규칙은 `game/src/econ/rules.ts` 하나 (서버 번들과 기기 오프라인 모드가 공용). 기기 쪽 진입점은 `game/src/econ.ts` 의 `act()`.
- 결제: `$onItemPurchased` 훅에서 바로 지급 (purchaseId 당 1회). 기기는 `claimPurchases` 로 상태·상자 공개만 받는다.
- 대전 보상: 서버 판정 뒤 서버가 지급 (실시간 대전 `finishMatch`, 봇전 `pvpBotResult`).
- 스테이지·무한 모드: `runStart` 기록 → `runEnd` 에서 웨이브당 2.5초 이상 지났을 때만 보상.
- 광고 보상: 직전 판 보상 2배는 10분 안 1회, 광고 소환권은 하루 3회 (광고 시청 자체는 서버가 확인할 수 없어 횟수로 막는다).
- 일일 퀘스트 진행도는 기기 기록이라 퀘스트마다 하루 1회만 지급.
- 경제 도입 전 계정은 첫 접속 때 한 번 옮긴다 (보석 2만·아이템 100·카드 2000 상한).
- 서버 테스트 14개 (`cd server && npm test`): 저장본 조작 무시, 결제 중복 방지, 서버 전용 동작 거부, 빠른 스테이지 결과 거부 등.

## 유닛 32종 · 카드 · 상자 · 뽑기

- 유닛 32종 = 일반 8 · 희귀 10 · 영웅 8 · 전설 6 (`UNITS`, 등급은 얻기 어려움 - 전력 차이가 아님). 설계: `docs/superpowers/specs/2026-10-12-unit-cards-design.md`
- 카드 1장 = 해금, 이후 카드는 레벨업 재료. 레벨업 = 카드(`CARD_NEED` 2·4·10·…·800, 희귀 ÷2·영웅 ÷5·전설 ÷10) + 보석
- **상자** (`chests.ts`): 대전 승리 시 칸 4개에 (`CHEST_CYCLE`: 나무·은·금·마법 순환), 한 번에 하나씩 열기
  (나무 30분 · 은 3시간 · 금 8시간 · 마법 12시간 · 전설 24시간), 보석으로 바로 열기(남은 3분당 1). 트로피 로드에도 상자 보상
- **뽑기**: 보석 1회 100 / 10회 900 (영웅 이상 1장 보장), 확률 일반 70 · 희귀 22 · 영웅 7 · 전설 1%
- 그림: `python tools/build_new_units.py` (CharaMEL 파츠, 없는 파츠는 오류로 멈춤) · 유닛 비교: `npx tsx tools/unitsim.ts`
- 봇 덱: 기본·로드 해금 + 트로피별 등급 (희귀 80, 영웅 300, 전설 800)

## 배치 전략 (사거리)

유닛은 자기 구역 앞 변과 양쪽 모서리 근처만 지킨다 (`GRADE_RANGE` 220/240/260/290/320, 태초만 맵 전체, 레인저 x1.3).
어떤 유닛도 닿지 않는 길 구간은 전장에 빨갛게 표시된다 → 구역을 끌어 바꿔 구멍을 메우고,
PvP 에선 상대 구멍 쪽으로 몹을 던진다 (봇도 약한 구역을 노린다).

## 밸런스

`tools/simulate.ts` 자동 플레이어로 검증한 곡선 (합성 공격력 등급당 3배, 시작 골드 200, 처치 골드 3, 상성 1.0/0.9):

**무한 모드 (평균 도달 웨이브, 성장률 +17%):** 연구 0 → 38.8 / 1/4 → 45.5 / 절반 → 46.6 / 3/4 → 49.5 / 풀 → 50 (100% 클리어)

**캠페인 (클리어율, 연구 0·유닛 Lv1, 성장률 +11.5%):** 챕터1 100% / 챕터2 약 90~100% / 챕터3 약 65~100%.
연구 1/4 만 해도 전 스테이지 100% - 누구나 깰 수 있게 쉽게 맞춤 (`npx tsx tools/simulate.ts stages 10`).

## 참고

- 스프라이트는 96×128(32×32 3열×4행) RPG Maker 형식, CharaMEL(ぴぽや 32x32 男女 파츠)로 만든 것.
  해금 유닛 5종(레인저/빙결술사/성기사/폭격수/암살자) 30장은 `tools/build_unit_sprites.py` 가 같은 파츠를
  합성해 만든다 (`tools/charamel.py`). CharaMEL 의 `characters/pipoya32x32_男女` 폴더를 `Asset/charamel/` 에 복사해 두고 실행.
- PvP 는 각 클라이언트가 자기 필드를 시뮬레이션하고 서버는 매칭·중계·판정만 담당한다.
  같은 `seed` 로 웨이브 구성(종족·몹 종류)이 양쪽 동일. 배속 1x 고정, 연구 미적용, 유닛 레벨 적용.
- 백그라운드 탭: 일반 모드는 멈추고, PvP 는 타이머 보조로 계속 진행된다.
